# Validation and release notes — 1.1.0

## Automated checks

Run `node --test tests/*.test.mjs` using Node.js 20 or later. No installation is required.

18 tests cover deterministic pixel processing, bounds, transparency, invalid dimensions, signed byte matching, metadata tampering, malformed signatures, substituted fingerprints, unknown signers, wrong trusted keys, and isolation of offline caches from unrelated sites on the same origin.

These checks validate software behavior. They do not measure resistance to AI editing.

## Reliability improvements

- Changing a setting immediately disables exports until the new preview finishes.
- Proof metadata comes from the same render snapshot as its hashed PNG.
- New image selection invalidates pending work; late decodes cannot replace newer selections.
- Decoded images above 40 megapixels are rejected; the browser must still initially decode input, so this is not a complete defense against malicious files.
- Offline updates only remove this application's caches and only intercept its known shell assets.
- Microtexture starts at zero and has no model-efficacy claim.
- Signing keys and photos remain in memory until reload; Clear session reloads the app. Previously downloaded files remain on disk.
- A restrictive content security policy excludes third-party scripts and remote image sources.

## Release limitations

This is an educational custom proof format, not C2PA. Signatures bind bytes to a key, not identity, legal ownership, consent, camera origin, or scene truth. Exact-byte verification fails after recompression or resizing. No ML adversarial optimization or universal AI protection is implemented. No cross-browser or physical mobile-device test is claimed.
